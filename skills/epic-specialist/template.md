## Workflow Exit Criteria

| Status | Exit Criteria |
|---|---|
| **New** | Assignee identified, goal documented, initial acceptance criteria drafted, parent Feature or Initiative linked (if applicable) |
| **Refinement** | Acceptance criteria finalized, child stories/tasks created, story points estimated, dependencies identified |
| **Backlog** | Refinement complete, stories linked, priority assigned — queued pending sprint capacity |
| **In Progress** | All child stories/tasks in active delivery |
| **Review** | All child stories/tasks complete; undergoing final acceptance criteria verification |
| **Closed** | All acceptance criteria met, all child issues closed, resolution value set |

## Scope Signals — Questions to Consider

> These are guidelines, not hard rules. Surface these as questions, not rejections.

- Is the Epic scoped to **fit within a single release**? If it spans multiple releases, consider splitting or confirm with the team that the broader scope is intentional.
- Is the Epic **team-specific**? If it spans many teams with no clear owner team, it may be better represented as a Feature.
- Is there a **Parent Link** to a Feature or Initiative? Epics don't require parents, but if this Epic clearly implements a Feature, the link should exist.
- Is the Epic being used to **keep work open permanently** rather than to deliver a specific goal? Components or Labels may be more appropriate.
